NODE 01
先討論（Planning）

定義受眾為「完全沒學過 RAG 的同學」，決定教學順序與避開艱深公式。

NODE 02 / LOOP A
來源整理（Ingest）

逐篇記錄可信來源的網址、作者、文獻主題與可支持的知識要點；六篇全部形成原始筆記。

NODE 03
LLM 整理（Wiki Synthesis）

根據筆記由 LLM 整理 10 個概念頁，保留文獻出處和 Wiki 條目間的 crosslink。

NODE 04 / LOOP B
檢查（Lint Gate）

驗證每頁有來源、來源存在、Wiki 連結有效、簡報來源可被對應 Wiki 支持。出錯則阻止 build。

NODE 05
製作教學 HTML

同一份 Wiki 知識結構生成 Wiki 入口與投影片，兩個網站都帶有來源反向連結。

NODE 06 / REVIEW
人工審查與再修正

檢查初學者能否理解、虛構例子是否被誤解為真實政策，以及重要主張是否忠於原文。若不合格回到相應節點。

實際執行：故意注入一個壞引用，檢查有沒有擋下來

測試時把某張投影片的來源改成不存在的 S99（只是測試副本），執行 check 得到 FAIL；修正為已被 Wiki 條目引用的來源後重新檢查，得到 PASS。這個測試驗證的是來源 ID 一致性，不代表引用內容已被自動做語意查核。

反思與修改

最容易出錯
簡報引用／Wiki 對應節點

若只在簡報最後才加上來源，容易出現來源不存在或不是來自該 Wiki 頁面的問題。

修改後
把檢查移到 HTML 產生之前

從「先 build 再補救」改為「先驗證再 build」，修正時不需反覆調整已產生的 HTML。

什麼仍需要人工確認？

檔案 SHA-256、來源 ID、交叉連結及數量等可以被程式自動檢查，但「這份文獻是否真的支持這句話」以及「是否教得夠清楚」仍須逐段人工核對。公開案例中的訂單、政策為虛構演示，不能作為實際決策依據。
